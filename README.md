# 一起记 · 小团队共同账本

[![Docker build](https://github.com/VANORA-Team/team-ledger/actions/workflows/docker-publish.yml/badge.svg)](https://github.com/VANORA-Team/team-ledger/actions/workflows/docker-publish.yml)

供扁平化小团队使用的 Web + Telegram / 飞书记账系统。每位成员都有独立账号，拥有相同的管理权限。公账支出直接扣款，成员垫付记账后待报销、实际付款后登记报销，无需审核，没有分类功能。

## 已实现

- Web 表单记账，以及 Web / Telegram 的 AI 自然语言记账助手：一次可说一段话，拆成多笔新增 / 修改 / 作废 / 报销 / 查询，核对清单后执行。
- 公账支出、成员垫付、团队收入、多币种、日期、备注、PNG / JPG / PDF 凭证。
- 报销列表与账目详情可直接查看凭证：PNG / JPG 在页面内预览，支持原尺寸查看；PDF 在新窗口打开。
- 记录谁垫付；草稿、待报销（含部分报销）、已报销、作废，以及逐笔操作记录。
- 未付款支出可修改，支持逐笔或批量填写本次报销金额，允许分次报销；重复请求不会重复入账或扣款。
- 记账用途 / 收入说明、备注均选填，留空也可保存草稿或入账；列表中的空说明显示为“未填写说明”，原始记录与导出保留空值。
- Telegram 按钮记账：选择币种 → 输入金额 → 预览确认。预览中可选填用途、备注，并修改金额、币种、日期和成员；编辑用途或备注时发送 `-` 清空，升级前停在用途步骤的草稿也可发送 `-` 跳过。付款参考号和作废原因不受此规则影响。
- Telegram AI 自然语言记账：私聊或 `/ai` 一次说一段话，生成可逐项勾选的操作清单；确认后才入账。
- Web / Telegram 资金计算支持模拟新增收入、指定报销预算或勾选项目、查看余额 / 结余 / 缺口；Telegram 可按本次安排及实际余额一键登记报销。
- Telegram 菜单支持个人 / 团队待报销、最近账目分页、今日 / 本月收支、余额与具体付款项目。
- Telegram 可修改未付款支出，填写备注并二次确认后登记付款或作废；会检查并发修改和重复操作。
- 可配置币种、默认记账币种、资金汇总参考币种。
- 自动查询公开汇率 API，计算今日收入、累计可用资金、可预留报销、可安排付款、结余与缺口。
- 导出带 UTF-8 BOM 的 CSV，金额和币种分列；导出文本做了公式注入防护。
- SQLite 持久化；不需要 Redis、PostgreSQL、Node 或前端构建工具。
- 本地、WebDAV、S3 兼容存储桶完整备份与恢复；支持按小时、每天或每周自动备份、保留份数、完整性校验和恢复前保护副本。

## 本地启动

需要 Python 3.12 或更新版本。Windows PowerShell 中进入项目目录：

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
Copy-Item .env.example .env
.\.venv\Scripts\python run.py
```

打开 **http://127.0.0.1:8765**，创建第一个团队账号。之后任何成员都可以在「团队成员」创建新账号。

首次启动没有预设账号、密码或示例账目。密码不能为空，不限制字符数。所有已启用成员均可管理成员、重置密码、修改设置、登记收入和报销付款，符合扁平团队的共同管理方式。系统会阻止停用最后一个可用账号。

原有环境已安装依赖时，直接 `python run.py` 即可。

## 账务规则

1. 支出分为「公账支出」和「成员垫付」。公账支出确认入账后直接扣减公账余额，不进入待报销；成员垫付记账后进入待报销，实际报销后才扣减公账余额。
2. 团队收入增加公账余额。成员垫付在**实际转账后登记本次已报销金额**，按真实付款币种与金额扣减资金，支持分次付款。公账支出无需再次登记报销，避免重复扣款。
3. 草稿、已作废支出不进入待报销；已作废收入不增加资金。
4. 新增 / 记错的未付款账目可以填写原因作废。已有任何报销记录的支出不能作废。未结清时仍留在待报销列表，全部结清后不能继续付款。已作废账目默认不出现在收支明细、总览和最近账目，可在报销管理的「已作废」标签或 Telegram 已作废列表中查看；确认后可永久删除，账目、操作记录、付款记录和凭证会一并清除，无法恢复。
5. 没有报销记录的草稿、待报销垫付和已入账公账支出可以修改；部分或全部报销后锁定账目编辑，防止修改金额、币种或垫付成员破坏历史。全部历史操作和逐次付款记录可查看。
6. 每笔记录保留原始币种与金额，金额按货币最小单位以整数存储。日元默认 0 位，人民币 / 美元默认 2 位。
7. 所有成员都可直接登记报销付款，不需要其他成员批准，操作人和付款备注会被记录。

旧版本升级时，待审核与已审核未付款支出自动迁移为待报销，已驳回支出回到草稿。金额、原币种、已付款记录和历史操作记录保留。

## 资金如何计算

统一以设置中的参考币种换算：

```text
可用资金 = 团队收入 − 公账支出 − 已报销付款
全部待报销 = 所有待报销支出的未报销余额
本次报销范围 = 全部待报销，或手动勾选项目的未报销余额
本次安排报销 = min(max(可用资金, 0), 本次报销范围, 本次报销预算)
安排后结余 = 可用资金 − 本次安排报销
安排后仍待报销 = 全部待报销 − 本次安排报销
资金缺口 = max(全部待报销 − max(可用资金, 0), 0)
可安排付款 = 本次安排报销
```

例如：收到 1,000 USD，参考汇率为 1 USD = 7 CNY（仅示例），团队当前待报销 3,000 CNY、没有之前的收入和报销付款，则预留 3,000 CNY，结余 4,000 CNY。

「资金计算」默认按最早发生日期自动安排全部待报销，可切换为「指定报销预算」或「手动选择报销项目」。未指定预算时不额外限额；预算采用当前汇总参考币种，可填 0 暂不安排报销。手动模式仅安排勾选项目，不勾选则不安排任何项目。未安排和未结清的余额继续待报销；这些选择只用于本次计算，不会修改账目或自动付款。

可模拟一笔**尚未入账的新收入**，在当前余额上加上该金额，计算资金安排。Web 新增进账留空时直接安排当前余额。模拟不会生成真实收入，也不会改变实际公账余额。已经登记的收入不要再输入一次模拟，否则会重复计入预演。

所选范围内优先安排发生日期最早的记录。预算或余额不足时显示某笔的部分安排；实际付款后，可在 Web 或 Telegram 填写本次已报销金额，剩余部分继续待报销。

「资金计算」的伙伴报销安排会展开到具体项目，显示项目用途、原币种金额、结算参考金额和该项目的建议付款金额；如果余额不足，会标记为部分安排或暂不安排。

汇总采用本次报告获取 / 缓存的参考汇率，对历史原币种金额重新换算；它是资金规划参考，**不是锁定的历史记账汇率，也不是实际银行结算金额或会计利润**。没有实际换汇的不同币种资金，能否在付款时使用，由团队自行确认。系统不会执行转账。

## 部分报销与付款币种

Web 在账目详情或报销管理中点击「登记已付款」，逐笔填写**本次**实际付款金额；金额不是累计值。每笔可以选择记账货币，或团队设置的结算货币（汇总参考币种）。待报销列表包含部分报销，详情、付款建议、成员汇总与 CSV 均显示已报销和剩余款。

例如记账 100 USD，结算货币为 HKD，确认时参考汇率为 1 USD = 7.80 HKD：本次实际支付 312 HKD，抵扣 40 USD，累计已报 40 USD、剩余 60 USD；下一次也可改用 USD 报销。每次保留实际付款金额 / 币种、抵扣的原币金额、操作人、时间、备注和汇率快照。资金余额按实际付款扣款，不会把 312 HKD 当作 312 USD，也不会对已确认的付款重新折算抵扣额。

跨币种确认换算有效 30 分钟；结算货币采用服务器取得的每日参考汇率，汇率不可用时可继续按记账货币登记。按币种最小单位四舍五入，填写「剩余全额」对应金额会结清原账剩余，避免尾差。界面中的后续参考换算会随每日汇率变化，历史付款和已抵扣的记账金额保持不变。该汇率用于报销抵扣，并非银行实际换汇成交价。

旧版已全额报销的账目自动生成一次历史付款明细，保留原日期、备注和金额；迁移可重复执行，不会重复扣款。

## 公账支出与成员垫付

Web 记账表单可选择「公账支出」「成员垫付」或「团队收入」。收支明细支持分别筛选两种支出，详情和 CSV 均保留支出方式。公账支出中的成员为经手成员；成员垫付中的成员为实际垫款人。

例如公账收入 1,000 CNY，公账支付服务器费用 200 CNY，成员另垫付打车 100 CNY，则公账可用余额为 800 CNY、待报销为 100 CNY；报销其中 40 CNY 后，公账余额为 760 CNY、待报销为 60 CNY。

公账支出草稿不扣款，确认入账后扣款；作废后恢复相应余额。公账支出不参与报销预算、报销项目选择或一键报销。成员垫付沿用部分报销、多币种付款和操作记录。

盈利分红功能已移除。升级时，原成员支出自动保留为成员垫付；已有独立分红记录转换为历史公账支出，保留原金额、币种、操作人、备注、时间和汇率快照，公账余额不变。更早版本的已分配收入也会一并转换；迁移可重复执行，不会重复扣款。

## Telegram 资金计算与一键报销

打开菜单「资金与付款项目」或发送 `/funds`，查看资金、待报销、建议预留、结余、缺口和具体项目。点击「模拟新进账」选择币种并输入金额，只试算，不写入账本；需要记录真实进账时，点击相应按钮后核对收入预览并保存。

点击「设置报销预算」填写本次使用的结算币种金额，或点击「选择报销项目」分页勾选；可点「恢复自动安排」取消本次限制。「按实际余额一键报销」沿用本次预算或所选项目，始终使用已入账的真实资金，排除模拟进账，并扣除已入账公账支出。选择「按结算货币」或「按各笔记账货币」，机器人按最早发生日期生成逐笔清单；预算或余额不足时，只安排能覆盖的部分。每笔列出项目、成员、实际付款、抵扣记账金额及剩余待报，支持翻页、填写批次付款备注。

完成真实转账并核对清单后，点击「确认已转账，一键登记」一次保存全部付款。账本或结算设置变化、确认 / 汇率快照过期时整批拒绝，需重新计算；重复点击不重复扣款，剩余部分继续待报销。机器人只记录付款，不执行银行 / 链上转账。原币种转账之间是否已实际换汇，仍由团队确认。

## 汇率 API

默认使用 [Frankfurter](https://frankfurter.dev/) 的公开接口，无需 API Key：

```dotenv
FX_API_URL=https://api.frankfurter.app/latest
FX_CACHE_HOURS=12
```

兼容 v1 的 `base/date/rates` 返回格式，也支持 `https://api.frankfurter.dev/v2/rates` 的数组格式。数据为每日参考汇率，周末 / 节假日可能返回最近工作日，界面会显示每对汇率的来源与日期。

- 同币种计算不访问汇率服务。
- 接口失败且有缓存时，明确提示缓存和日期。
- 某币种缺少汇率且没有缓存时，暂停合并计算；原币种账目仍可查看和记录。
- 只有服务商支持的币种才能自动换算。自行增加币种不会保证 API 一定支持它。
- 缓存与原始账目一起保存在 SQLite。

## 配置 AI：Web 和 Telegram 共用

在 `.env` 填写你拥有的 OpenAI 兼容 Chat Completions 服务，然后重启 Web / bot：

```dotenv
AI_BASE_URL=https://api.openai.com/v1
AI_API_KEY=填写你的密钥
AI_MODEL=填写接口实际支持的模型名称
AI_RESPONSE_FORMAT=json_object
```

`AI_BASE_URL` 不要包含 `/chat/completions`，程序会追加它。兼容结构化输出的服务可设置 `AI_RESPONSE_FORMAT=json_schema`；默认 `json_object` 要求服务支持 JSON 输出模式。

支持一次说一段话，AI 会拆成多条可核对的操作：

```text
昨天我垫了打车 35 元，老王垫的聚餐 240 元，收到客户尾款 2000 美元；
把上周那笔重复的 #18 作废；老王所有待报销都报掉；
顺便告诉我这个月花了多少、现在还能报多少。
```

覆盖的记账能力：

- 批量新增公账支出 / 成员垫付 / 团队收入，支持草稿、指定垫付成员、日期、币种、备注；收入统一记为团队在账。
- 修改尚无报销记录的支出；作废账目；草稿记入账本。
- 单笔部分 / 全额报销，按记账货币或团队结算货币；按可用资金、指定成员、项目或总预算批量登记报销。总预算采用团队结算币种，可与项目筛选组合。
- 永久删除已作废账目（会清除账目、操作记录、付款记录和凭证，无法恢复）。
- 只读查询：明细、统计、余额、待报销、资金规划、模拟进账、单笔详情。查询会直接回答，不需要确认。

安全规则：

- AI 只生成**待确认操作清单**，不会直接写入。你可以在 Web 勾选 / 取消每一项，或点「在表单中修改」补充凭证；Telegram 中可逐项勾选后一次确认。
- 确认时会在一个事务里重新校验金额、币种、日期、账目版本和付款报价；任一项已变化则整批不写入。
- `pay_entry` / `batch_pay` 只登记**已经实际完成**的报销转账，不会发起付款。公账支出直接入账扣款，不能再次报销；批量报销必须基于最新账本，放在本次清单的其他写操作之前。
- 一次最多 20 个动作、约 120 笔账目上下文；操作清单 30 分钟内有效。超过限制或描述有歧义时，AI 会先追问，不会猜测。
- 交易记录、账目描述和历史对话都只作为数据，不执行其中的指令。
- 支持追问：Web 助手保留当前对话上下文，可以直接说「把第二笔改成 50」；Telegram 在清单确认前继续发消息，会带着上一版清单重新整理。已执行的清单不会重复执行。

发送给 AI 接口的内容：**当前输入、最近账目摘要（编号、日期、类型、金额、币种、用途、备注摘要、成员、状态、剩余/已报销金额）、资金概况（含公账支出、已报销与待报销）、成员姓名、币种配置、当前日期/时区、最近几轮对话**。不会发送凭证文件、密码、会话令牌或 Telegram 绑定信息。可用 `AI_CONTEXT_ENTRIES` 调小上下文条数（最小 20）。密钥仅在服务端使用，不通过配置 API 返回到浏览器。

可选配置：

```dotenv
AI_TIMEOUT=40              # 单次模型调用超时秒数
AI_CONTEXT_ENTRIES=120     # 发送给模型的最近账目条数（会优先保留可操作账目）
AI_CONTEXT_CHARS=60000     # 上下文 JSON 的字符上限
AI_MAX_ACTIONS=20          # 单次最多生成的操作数
```

未配置密钥或模型时会给出提示，表单和按钮方式正常工作。当前不支持发票 OCR、语音输入；凭证需在 Web 账目详情或新建表单中上传。成员账号、密码和团队设置不通过 AI 修改。

接口实现参考 [OpenAI Chat API](https://developers.openai.com/api/reference/resources/chat)。不同兼容服务的模型和 JSON 模式支持可能不同，需使用该服务实际提供的配置。

## 接入飞书

飞书使用**企业自建应用机器人**和长连接，支持与 Telegram 相同的按钮菜单、私聊和允许名单群聊。成员须先私聊绑定 Web 账号；可通过按钮记账、查询、登记报销、资金计算，配置 AI 后也可用自然语言。

1. 在飞书开放平台创建企业自建应用，启用机器人，申请「获取用户发给机器人的单聊消息」（`im:message.p2p_msg:readonly`）、「接收群聊中@机器人消息事件」（`im:message.group_at_msg:readonly`）及「以应用的身份发消息」（`im:message:send_as_bot`）权限。
2. 运行 `python -m app.feishu`；Docker 环境运行 `docker compose --profile feishu up -d --build`，然后在 Web「机器人与 AI」填写飞书 App ID 和 App Secret。也可使用环境变量 `FEISHU_APP_ID`、`FEISHU_APP_SECRET`；网页配置优先生效，修改后 worker 自动重连。密钥保存在数据库和数据库备份中，不会通过 API 返回。更换应用 ID 前需解除所有成员的飞书绑定。每个数据库只运行一个飞书 worker，也不要让其他服务使用同一个飞书应用接收事件。
3. 在应用「事件与回调」的事件配置中选择「使用长连接接收事件」并添加「接收消息」（`im.message.receive_v1`）；在回调配置中选择长连接并添加「卡片回传交互」（`card.action.trigger`）。保存长连接订阅方式前，worker 必须已经在线。发布应用新版本并完成管理员审批，确保成员在应用可用范围内。
4. 成员登录 Web「机器人与 AI」，生成飞书绑定码，在飞书机器人**私聊**发送 `绑定 绑定码`。绑定码有效 10 分钟，一次使用后失效。Telegram 与飞书绑定彼此独立。
5. 私聊发送 `/start` 打开按钮菜单。也可以发送 `公账支出 35 CNY 打车`、`成员垫付 35 CNY 打车` 或 `收入 100 CNY 收款`（旧的 `支出` 命令仍按成员垫付处理），核对清单后按提示发送 `确认 确认码` 才会入账；发送 `取消 确认码` 可取消。也可发送 `最近账目`、`余额`、`待报销` 或 `帮助`。配置 AI 后可说「昨天打车 35 元，再记一笔午餐 20 元」或自然语言查询，写操作仍须确认；一次文字确认会执行预览中的全部有效操作；按钮菜单可逐项选择。
6. 群聊中 @机器人发送 `/groupid` 获取群 ID，在 Web「团队设置」中添加到飞书允许名单。群成员须先私聊绑定；在群内使用命令需 @机器人，填写金额等内容时请 @机器人并回复对应的机器人提示。按钮只允许发起者操作。

长连接不需要公网回调地址。收到的消息和待发送回复先持久化；重复消息和确认不会重复入账，发送失败会重试。飞书发送接口的去重有平台有效期，长时间断线后回复可能重复。输入和已发送回复在处理成功后清空，消息 ID 用于防重。飞书应用密钥只存放在服务端数据库或环境变量中。

飞书配置步骤与权限参考：[使用长连接接收事件](https://open.feishu.cn/document/ukTMukTMukTM/uYDNxYjL2QTM24iN0EjN/event-subscription-configure-)、[机器人概述](https://open.feishu.cn/document/client-docs/bot-v3/bot-overview)。

## 接入 Telegram

1. 在 Telegram 的 BotFather 创建机器人，取得 Token。
2. 在 `.env` 设置 `TELEGRAM_BOT_TOKEN`。
3. 保持 Web 运行，另开终端，在同一项目目录启动：

```powershell
.\.venv\Scripts\python -m app.bot
```

4. 每位成员登录 Web →「机器人与 AI」→ 生成绑定码。
5. 在机器人的**私聊**发送 `/start 绑定码`。绑定码 10 分钟有效，使用后立即失效。
6. 发送 `/start` 查看按钮菜单，`/expense` 记录公账支出，`/book` 记录成员垫付，`/income` 记录收入。

命令：

| 命令 | 用途 |
| --- | --- |
| `/start` | 展示记账按钮菜单 |
| `/expense` | 逐步记录一笔公账支出，确认后直接扣减公账余额 |
| `/book` | 逐步记录一笔成员垫付 |
| `/income` | 逐步记录一笔团队收入 |
| `/ai 今天打车花了35元` | AI 识别；也可一次描述多笔、修改、作废、报销或查询，核对清单后入账 |
| `/summary` | 查看自己的待报销，按原币种列示 |
| `/recent` | 分页查看最近账目（默认不含已作废），点项目打开详情；可进入已作废列表永久删除 |
| `/team` | 分页查看团队待报销明细 |
| `/funds` | 查看余额、结余、资金缺口与建议付款的具体项目 |
| `/today` | 今日收入、公账支出与成员垫付，按原币种分别列示 |
| `/month` | 本月收入、公账支出与成员垫付，按原币种分别列示 |
| `/cancel` | 取消当前草稿 |
| `/help` | 使用提示 |

私聊直接发送自然语言也可触发 AI。正在填写按钮表单时，普通文字会用于当前金额 / 用途步骤；用 `/cancel` 清空或 `/ai ...` 另起识别。

默认只允许已绑定账号的私聊。要在群组中使用，在 Web「团队设置」添加群组 ID（如 `-100...`），群内每个使用者仍需先私聊绑定。不要把绑定码发到群里。群中用命令 `/expense`、`/book`、`/ai ...` 或按钮开始；填写金额、用途、付款备注等信息时，**回复机器人发给你的输入提示**。机器人会验证回复归属和当前步骤，普通群聊不会触发 AI 或填入草稿。话题群中的回复保留在原话题。

主菜单入口为 `/start`。列表支持上一页 / 下一页，按钮切换尽量编辑原消息减少刷屏。每笔账目可显示原币种及每日参考汇率换算金额。草稿和操作确认码均绑定当前成员，过期或重复确认不能重复入账 / 付款。已入账支出若同时被 Web 修改，机器人会要求重新核对再保存。

在待报销详情点「登记已付款 / 继续报销」，选择「按记账货币」或「按结算货币」，填写本次实际已报销金额（发送 `全额` 结清剩余），再填写付款方式 / 参考号。确认页展示实际付款、抵扣的记账金额、累计已报和剩余待报，确认后才登记。金额或币种填错可在确认页重新选择；群聊中仍需回复对应提示。所有成员都可操作，凭证在 Web 上传和查看，机器人不会发起真实转账。

机器人采用长轮询，不需要公网 Webhook，但服务器必须能访问 Telegram。同一个数据库只启动一个机器人进程，不能与其他服务争用相同 Token 的更新。若之前配置过 Webhook，worker 会提示先在原服务停用，不会擅自删除。

需要代理时配置 `TELEGRAM_PROXY_URL=http://127.0.0.1:7890`。HTTP 代理必须能连通 Telegram；此项不作用于 AI / 汇率接口。

更新处理、草稿确认、账目写入及待发回复放在数据库事务中。重复 Telegram 更新或重复确认不会重复入账。回复使用持久队列重试；网络故障时记账提交不会回滚，极端断线时回复可能重复，但账目保持防重。

相关接口参考 [Telegram Bot API](https://core.telegram.org/bots/api)。

## Docker 部署

推荐直接使用 GitHub Actions 构建的 GHCR 镜像：

```sh
docker pull ghcr.io/vanora-team/team-ledger:latest
cp .env.example .env
# 编辑 .env
docker compose pull
docker compose up -d --no-build
# 配置机器人后
docker compose --profile telegram up -d --no-build
```

Web 和 bot 使用同一镜像，数据通过命名卷持久化。要固定到某个版本，在 `.env` 中设置 `LEDGER_IMAGE=ghcr.io/vanora-team/team-ledger:版本号`，再执行 `docker compose pull` 和 `docker compose up -d --no-build`。

也可从源码自行构建：

```sh
cp .env.example .env
# 编辑 .env
docker compose up -d --build
# 配置了机器人后，额外启动 bot
docker compose --profile telegram up -d --build
```

Web 默认只映射宿主机 `127.0.0.1:8765`。通过反向代理提供团队访问时，设置：

```dotenv
PUBLIC_URL=https://你的记账域名
COOKIE_SECURE=true
```

使用 HTTPS 反向代理到 `127.0.0.1:8765`。先通过本机 / SSH 隧道完成首个账号初始化，再开放域名访问，避免首次初始化页面被别人抢先使用。不要直接公网暴露尚未初始化的实例。

Docker 的 Web 和 bot 共用 `ledger-data` 命名卷。数据库适合单台服务器上的小团队，不要放到 NFS 或多主机同时写入。

GitHub Actions 自动运行账务测试、构建并启动 AMD64 容器、检查健康接口和初始空账本，再发布 AMD64 / ARM64 双架构镜像。发布后还会在无登录凭据的环境验证多架构清单和匿名拉取。ARM64 在构建时通过 QEMU 模拟，不包含 ARM64 运行验证。

### 自动发布规则

- 推送 `main`：发布 `latest`、`main` 和完整提交 SHA 标签。
- 推送 `v1.2.3` 这样的版本标签：发布 `1.2.3`、`1.2` 和提交 SHA 标签。
- Pull Request：只运行测试，不发布镜像。
- 可在 Actions 的「Test and publish Docker image」中手动运行。
- 使用仓库自带的 `GITHUB_TOKEN` 发布 GHCR，无需额外填写 Docker Hub 密钥。

镜像地址：`ghcr.io/vanora-team/team-ledger`。构建状态和镜像摘要见 [GitHub Actions](https://github.com/VANORA-Team/team-ledger/actions/workflows/docker-publish.yml)。

## 保存与备份

默认数据在 `data/`：`ledger.sqlite3`、相关 SQLite WAL 文件，以及 `receipts/`。可用 `DATA_DIR` 指定绝对目录。运行期间 SQLite 数据库与凭证都需要保留。

在 Web「团队设置 → 数据备份与恢复」操作。所有启用的团队成员都可管理备份，沿用团队共同管理权限。

- **本地备份**：选择「服务器本地」后点击「立即备份」。ZIP 保存在 `DATA_DIR/backups/`，可在列表下载到电脑；「从电脑恢复」可以上传原 ZIP 恢复。服务器本地文件仍依赖服务器磁盘，建议另存电脑或远程存储。
- **WebDAV**：填写已有服务目录的 URL、用户名、密码或应用密码，以及该目录下的备份子目录。点击「保存并测试 WebDAV」验证创建目录、写入、列表、读取和删除权限；选择 WebDAV 即可备份、查看、下载或恢复。使用 Basic 认证，建议使用 HTTPS。
- **S3 兼容存储桶**：填写存储桶、区域、Access Key ID、Secret Access Key、备份目录。AWS S3 可留空 Endpoint；其他服务填写完整 HTTP / HTTPS Endpoint。默认启用 Path style，可按服务要求关闭。凭据需要指定目录的 List / Get / Put / Delete 权限；存储桶须事先创建。点击「保存并测试 S3」验证后即可使用。
- 远程备份会同时保留一份服务器本地副本。多位置自动备份中某一位置失败时，其他位置仍会尝试，界面保留各位置结果。

勾选「启用自动备份」，选择每小时整点、每天指定时间或每周指定星期与时间，再选择一个或多个备份位置并保存。使用 `TEAM_TIMEZONE` 时区，默认 `Asia/Shanghai`。定时器由 Web 服务运行，每 15 秒检查；不需要 Windows 计划任务或系统 cron。停机期间错过的执行会在重启后补做一次，执行中断会在重启后重试；失败后 5 分钟重试。多个 Web 进程通过文件锁避免重复执行。Web 服务停止时不会生成新备份。

默认每个位置保留最近 30 份普通备份，可设置为 1–1000 份；只在新备份成功保存后清理本应用命名的旧备份，不会清理目录中的其他文件。恢复前保护副本在本地单独保留同样份数。

ZIP 包含通过 SQLite Online Backup 生成的一致性数据库快照、账目引用的凭证，以及记录文件大小和 SHA-256 的版本化清单。备份与恢复通过进程间锁协调 Web 和机器人数据库操作。恢复先检查 ZIP 路径、解压大小、校验和、数据库完整性、表结构与凭证引用，验证通过才保存恢复前副本并覆盖数据；安装失败时尝试回退数据库和凭证。保护副本以 `before-restore-` 开头，可以从本地列表下载或恢复。

恢复将覆盖成员、密码、账目、付款记录、团队设置、机器人绑定和数据库中的飞书应用配置；所有浏览器登录会话及待确认操作会失效，需使用**备份中的账号密码**重新登录。新服务器请先创建临时团队账号，再上传 ZIP 恢复。备份包含密码哈希及数据库中的机器人密钥，请妥善保管；`.env` 和其中的环境变量密钥需要单独安全保存。

远程备份凭据、自动备份设置与运行状态单独保存在 `DATA_DIR/backup-control.json`，密码和 Secret Access Key 不通过 API 返回，网页留空表示保留已保存值。该文件不打入 ZIP，恢复也不会覆盖目标服务器的备份连接和计划。恢复到新服务器后需重新配置这些连接；复制整个数据目录时请同时妥善保管此配置文件。

备份 ZIP 上传和远程下载默认限制为 256 MiB，可用 `BACKUP_MAX_BYTES=268435456` 调整；解压总量限制为该值的 4 倍，最多 50,000 个文件。反向代理的请求大小与超时需允许相应的 ZIP 上传。

仍可在停止 Web 与 bot 后复制整个数据目录或 Docker 命名卷做离线备份，恢复时一并恢复数据库和凭证。CSV 不能替代完整备份。

```sh
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
```
