# AI 自然语言记账助手

[← 返回主 README](../README.md)

系统内置一套面向 **Web、飞书 / Lark 与 Telegram 共用** 的 AI 自然语言记账引擎。用户可以用日常口语一次描述多笔收支、修改、作废、报销或统计查询，由 AI 生成可核对的操作清单，确认后在单个数据库事务内原子执行。

---

## 1. 在 Web 界面配置（无需环境变量或重启）

账本所有者登录后前往 **「机器人与 AI → AI 自然语言记账引擎」** 配置任意兼容 [OpenAI Chat Completions API](https://developers.openai.com/api/reference/resources/chat) 的服务，保存后立即对 Web、飞书与 Telegram 生效。

| 配置项 | 说明 |
| --- | --- |
| **启用开关** | 随时开启或停用 AI 引擎；停用不影响 Web 表单与机器人按钮菜单。 |
| **接口地址（Base URL）** | 例如 `https://api.openai.com/v1` 或任意兼容地址（含本地 Ollama / vLLM 等 `http://` 地址）。填写到 `/v1` 即可，若末尾包含 `/chat/completions` 会自动规范化去除。 |
| **API Key** | 仅保存在服务端 SQLite 数据库（`ai_config` 表），永不明文返回浏览器；编辑其他项时留空可保留原密钥，点击「清除配置」则清空密钥并停用。 |
| **模型名称** | 填写目标接口实际支持的模型标识。 |
| **返回格式** | 默认 `json_object`；支持结构化输出的服务可选 `json_schema`；不兼容 `response_format` 参数的服务可选「不指定（`none`，由提示词约束 JSON）」。 |
| **保存并测试连接** | 保存配置并立即发起一次极简 JSON 连通性测试，校验地址、密钥、模型与 JSON 输出，返回响应延迟与具体错误提示。 |

### 高级参数（网页折叠项）

| 参数 | 允许范围 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 请求超时（秒） | `5 – 180` | `40` | 单次模型请求超时时间（测试连接上限 30 秒） |
| 单次最多操作数 | `1 – 50` | `20` | 单份 AI 清单允许包含的最大动作数量 |
| 上下文最近账目条数 | `20 – 500` | `120` | 附带给模型的最近账目摘要条数上限 |
| 上下文字符上限 | `5000 – 200000` | `60000` | 附带账本上下文的总字符数上限 |

> **旧 `.env` 环境变量兼容**：若旧部署曾在 `.env` 中设置过 `AI_BASE_URL` / `AI_API_KEY` / `AI_MODEL` / `AI_RESPONSE_FORMAT` / `AI_TIMEOUT` / `AI_CONTEXT_ENTRIES` / `AI_CONTEXT_CHARS` / `AI_MAX_ACTIONS`，在 Web 端首次保存或清除配置前会自动回退读取；一旦在 Web 端保存或清除，以后均以数据库配置为准。

## 2. 使用方式与支持的能力

- **Web**：点击顶栏「AI 助手」（快捷键 `Ctrl K` / `Cmd K`）或在总览页快捷输入框发送；`Ctrl Enter` 提交解析。
- **飞书 / Telegram**：私聊直接发送自然语言，或在群聊中使用 `/ai ...`（飞书群内需 `@机器人`）。

### 示例输入

```text
昨天我垫了打车 35 元，老王垫的聚餐 240 元，收到客户尾款 2000 美元；
把上周那笔重复的 #18 作废；老王所有待报销都报掉；
顺便告诉我这个月花了多少、现在还能报多少。
```

### 覆盖的操作类型

- **批量新增**：公账支出、成员垫付、营业收入、公户转入；支持指定草稿状态、垫付 / 转入成员、发生日期、币种、区分商家货币与付款货币（如「买 OpenAI 商家显示 20 美元，实际扣款 145.6 元」）、手续费、外币手动汇率（如「付了 100 美元，汇率 7.25」）与备注（公户转入仅计入公户结余，不与营业收入一起计入经营利润）。
- **编辑与状态流转**：修改尚无报销记录的支出及已入账收入（含营业收入 / 公户转入归类、商家货币与商家金额、手续费及外币手动汇率调整或恢复自动汇率）、作废未付款账目、将草稿正式入账；**账本所有者（`owner`）**还可修改已部分报销或已报销的历史账目（财务管理员与普通成员不可修改），自动保留历史付款记录并按新总额同步报销状态。
- **单笔与批量报销**：按原记账货币或团队结算货币登记部分 / 全额报销；按当前可用资金、指定成员、具体项目或总预算（以团队结算币种计，可组合项目筛选）批量登记报销。
- **永久删除**：删除已作废账目（清除账目、操作记录、付款记录与凭证，不可恢复）。
- **只读查询**：直接回答明细、统计、可用余额、待报销、资金规划、模拟进账、单笔详情，无需二次确认。

## 3. 安全规则与防错机制

- **绝不静默写账**：所有写操作都会先生成**待确认操作清单**。Web 端支持逐项勾选 / 取消或点击「在表单中修改」补传凭证；飞书与 Telegram 交互卡片 / 按钮均支持逐项勾选后再一次性确认。
- **严格沿用角色权限**：普通成员只能通过 AI 处理本人未报销的成员垫付和只读查询；新增公账支出 / 收入、代他人操作、报销付款与永久删除需要财务管理员或账本所有者权限；修改已产生报销记录（部分报销 / 已报销）的历史账目**仅账本所有者（`owner`）**可用，财务管理员与普通成员均会被拒绝。
- **单事务重校验与 30 分钟有效期**：确认执行时在单个 SQLite 事务内重新校验金额、币种、日期、账目版本、账本快照与汇率报价；只要任一项在确认前已被修改或清单超时（30 分钟），整批操作直接拒绝，不会部分写入。已执行的清单带幂等键保护，不会重复执行。
- **不发起真实付款**：`pay_entry` / `batch_pay` 仅用于登记**已经实际完成**的转账。公账支出直接扣款，不能再报销；批量报销必须基于最新账本状态，且排在同清单其他写操作之前。
- **拒绝猜测与指令隔离**：超出单次动作数限制或表述存在歧义时，AI 会追问确认而非盲目补全。账目描述、历史记录和上下文均作为纯数据传入，不执行其中的提示词指令。
- **多轮追问**：Web 助手保留当前对话上下文，可直接说「把第二笔改成 50」；飞书 / Telegram 在清单确认前继续发消息，会基于上一版清单重新整理。

## 4. 数据隐私与当前边界

### 发送给 AI 接口的数据

仅包含：**当前输入、最近账目摘要（编号、日期、类型、金额、币种、用途、备注摘要、成员、状态、已报 / 剩余金额）、资金概况（含公账支出、已报销与待报销）、成员姓名、币种配置、当前日期与时区、最近几轮对话**。

**不会发送**：凭证图片 / PDF、OIDC 令牌或客户端密钥、登录会话令牌、飞书 / Telegram 绑定信息或机器人 / AI 密钥。如需减少上下文暴露量，可在 Web 高级参数中调低「上下文最近账目条数」（最小 20）或「上下文字符上限」。

### 当前不支持的能力

- 不支持发票 OCR 识别与语音输入；凭证需在 Web 新建表单或账目详情中上传。
- 不支持通过 AI 创建 / 停用成员、修改角色或更改团队与备份设置（成员与权限请在 Vanora 管理后台维护）。
