# 数据存储、备份与恢复

[← 返回主 README](../README.md)

系统将所有持久化文件集中保存在 `DATA_DIR`（默认 `./data`，Docker 默认 `/app/data`），并由 **账本所有者** 在 Web **「团队设置 → 数据备份与恢复」** 中管理备份与恢复。

---

## 1. 数据目录结构

| 路径 | 用途 | 是否打入备份 ZIP |
| --- | --- | --- |
| `ledger.sqlite3`（及 `-wal` / `-shm`） | 主账本 SQLite 数据库（含成员、角色、账目、付款、汇率缓存、飞书与 AI 配置等） | 是（通过 SQLite Online Backup 生成一致性快照） |
| `receipts/` | 账目上传的 PNG / JPG / PDF 凭证文件 | 是（仅打包被账目引用的凭证） |
| `backups/` | 服务器本地备份 ZIP 及 `before-restore-` 恢复前保护副本 | 否 |
| `backup-control.json` | WebDAV / S3 远程存储凭据、自动备份计划与运行状态 | **否**（恢复不会覆盖目标服务器的备份计划） |
| `.ledger.lock` 等锁文件 | 协调 Web 与机器人并发读写的跨进程文件锁 | 否 |

---

## 2. 支持的备份位置

- **服务器本地**：选择「服务器本地」点击「立即备份」，ZIP 保存于 `DATA_DIR/backups/`，可在列表中「刷新列表」、下载到电脑，或通过「从本地恢复」上传原 ZIP 恢复。由于本地文件仍依赖宿主机磁盘，建议配合远程存储或定期另存。
- **WebDAV**：填写已有目录 URL、用户名、密码（或应用密码）及备份子目录，点击「保存并测试 WebDAV」验证创建目录、写入、列表、读取与删除权限后即可使用。采用 Basic 认证，建议使用 HTTPS。
- **S3 兼容存储桶**：填写存储桶（须预先创建）、区域（如 `us-east-1`、Cloudflare R2 可填 `auto`，留空默认 `us-east-1`）、Access Key ID、Secret Access Key 与备份目录；AWS S3 可留空 Endpoint，其余兼容服务填写不含存储桶名称前缀或路径的服务端点（例如 `https://oss-cn-hangzhou.aliyuncs.com` 或 `https://<account_id>.r2.cloudflarestorage.com`）。MinIO 等自建对象存储建议开启 Path style，AWS S3、阿里云 OSS、腾讯云 COS 等虚拟主机风格服务请关闭 Path style。凭据需具备目标前缀下的 `List` / `Get` / `Put` / `Delete` 权限；点击「保存并测试 S3」验证通过即可启用。
- **本地保底与独立重试**：执行远程备份时会同时保留一份服务器本地副本；多位置自动备份若某一远程目标失败，系统会按退避间隔（5 / 15 / 30 / 60 分钟）仅对失败的远程目标重传该次快照，不会在重试期间重复生成本地快照或冲刷历史本地备份。

## 3. 定时自动备份与保留策略

在 Web 勾选 **「启用定时自动备份」**，选择执行频率（每小时整点、每天指定时间或每周指定星期与时间）及一个或多个目标位置并保存：

- **内置调度器**：由 Web 服务进程内置定时器每 15 秒检查一次，按 `TEAM_TIMEZONE`（默认 `Asia/Shanghai`）触发，**无需配置系统 cron 或 Windows 计划任务**。
- **容错机制**：停机期间错过的计划会在服务重启后补做一次；执行中断在重启后重试；失败后间隔 5 分钟重试；多进程场景通过文件锁避免重复执行。Web 服务未运行时不会生成新备份。
- **保留清理**：每个位置默认保留最近 `30` 份普通备份（可设为 `1 – 1000` 份）。仅在新备份成功写入后清理本应用命名的旧文件，不触碰目录中的其他文件；恢复前保护副本在本地单独按同样份数保留。

## 4. 备份包校验与恢复机制

### ZIP 完整性与安全校验

每份备份 ZIP 包含一致性数据库快照、账目引用的凭证以及记录各文件大小和 SHA-256 的版本化清单（`manifest.json`）。备份与恢复全程通过跨进程文件锁协调 Web 与机器人数据库访问。

执行恢复前，系统依次校验：
1. ZIP 路径安全、解压总体积与文件数上限；
2. 清单内全部文件的大小与 SHA-256 校验和；
3. 数据库完整性、外键约束、表结构兼容性（自动兼容缺少 `ai_config` / `member_events` / `oidc_*` 等新表或 `users.oidc_*`、`sessions.oidc_sid` 列的旧版备份并执行幂等迁移）、至少存在一位启用的账本所有者，以及全部凭证引用存在性。

### 恢复前保护与回滚

校验全部通过后，系统自动在本地生成一份以 `before-restore-` 开头的保护副本再覆盖当前数据；若安装阶段发生异常，自动尝试回退数据库与凭证。保护副本可直接从本地列表下载或再次恢复。

### 恢复后的影响范围

- **会覆盖**：本地成员投影与显示名称、历史账目、付款记录、团队设置、飞书 / Telegram 绑定，以及数据库中的飞书应用与 AI 配置。
- **不会覆盖**：目标服务器的 `DATA_DIR/backup-control.json`（远程备份凭据与定时计划）、`.env` 环境变量（含 `VANORA_OIDC_*`）以及 **Vanora OAuth 中的成员角色与启用状态**。恢复到全新服务器后，只需使用具备 `owner` 角色的 Vanora 账号登录即可上传 ZIP 恢复，完成后按需重新配置远程备份连接。
- **会话失效与权限重同步**：恢复会清除所有浏览器会话、进行中的 OIDC 流程与待确认操作，需使用已授权的 **Vanora 账号**重新登录；成员角色与启用状态将在登录与权限同步时自动以 Vanora OAuth 为准刷新（包括恢复切换 OIDC 之前的旧版备份，历史账目均完整保留）。

## 5. 敏感凭据与体积限制

- **密钥保管**：备份 ZIP 内包含成员身份绑定、数据库里的飞书应用密钥与 AI API Key（旧版兼容库中可能残留历史 `password_hash`），请妥善加密保存；`.env`（含 `VANORA_OIDC_CLIENT_SECRET`、Telegram Token 等）及 `DATA_DIR/backup-control.json`（含 WebDAV / S3 凭据，密码不通过 API 返回，网页留空表示保留原值）需另行安全保管。
- **大小上限**：上传与远程下载默认上限为 `256 MiB`，可通过 `.env` 的 `BACKUP_MAX_BYTES=268435456` 调整；解压总量限制为该值的 4 倍且最多 50,000 个文件。反向代理需相应放宽请求体大小与超时时间。
- **离线冷备份**：也可在停止 Web 与机器人进程后直接复制整个 `DATA_DIR` 或 Docker `ledger-data` 命名卷（恢复时务必将数据库与 `receipts/` 一并恢复）。**Excel 导出仅含账目报表与压缩预览图，不能替代完整备份**。
