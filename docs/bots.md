# 飞书 / Lark 与 Telegram 机器人接入指南

[← 返回主 README](../README.md)

飞书 / Lark 与 Telegram 机器人共享同一套账务规则、成员角色权限、资金计算、一键报销与 AI 记账引擎，均采用长连接 / 长轮询主动出站模式，**无需暴露公网 Webhook 回调地址**。

> **通用约束**
> - 每个 SQLite 数据库只运行 **一个** 飞书 worker 和 **一个** Telegram worker，且不要与其他服务共用同一个应用凭证或 Bot Token。
> - 成员需在 Web「机器人与 AI」生成 **10 分钟有效、一次性** 的绑定码，并在机器人**私聊**中完成绑定（请勿将绑定码发送到群聊）。Telegram 与飞书绑定相互独立，在只读「团队成员」页可查看每位成员的绑定状态；当成员在 Vanora OAuth 被降级、撤权或停用时，机器人待确认草稿/卡片会立即失效并停止响应。
> - 若在 `.env` 配置了 `PUBLIC_URL`，机器人账目详情卡片会自动附带 `#entry/<id>` 直达按钮，方便跳转 Web 查看详情或上传凭证。
> - 机器人仅登记账目与已完成的报销付款，**不会发起真实银行或链上转账**。

## 1. 接入飞书 / Lark

支持中国版飞书（`open.feishu.cn`）、国际版 Lark（`open.larksuite.com`）与私有化自定义 `https://` 域名，并提供交互卡片菜单与工作台 WebView 适配。

### 1.1 开放平台配置

1. 在飞书 / Lark 开放平台创建**企业自建应用**，开启「机器人」能力。
2. 申请以下权限：
   - 获取用户发给机器人的单聊消息：`im:message.p2p_msg:readonly`
   - 接收群聊中 `@机器人` 消息事件：`im:message.group_at_msg:readonly`
   - 以应用的身份发消息：`im:message:send_as_bot`
3. 先启动飞书 worker（长连接订阅保存前要求客户端已在线）：
   - 本地运行：`python -m app.feishu`
   - Docker 运行：`docker compose --profile feishu up -d --no-build`（源码构建改为 `--build`）
4. 账本所有者登录 Web **「机器人与 AI」**，填写飞书 **App ID**、**App Secret** 与服务区域（`feishu` / `lark` / 自定义 `https://` 地址）并保存。
   - 也可通过 `.env` 的 `FEISHU_APP_ID`、`FEISHU_APP_SECRET`、`FEISHU_DOMAIN` 配置，Web 数据库配置优先生效。
   - 修改配置后 worker 自动重启重连；网页实时展示在线状态、机器人名称与最近错误。
   - 密钥保存在数据库及数据库备份中，不通过 API 返回。**更换 App ID 前需先解除所有成员的飞书绑定**。
5. 回到开放平台「事件与回调」：
   - **事件配置**：选择「使用长连接接收事件」，添加「接收消息」（`im.message.receive_v1`）。
   - **回调配置**：选择长连接，添加「卡片回传交互」（`card.action.trigger`）。
6. 发布应用版本并完成管理员审批，确认目标成员在应用可用范围内。

### 1.2 绑定与交互使用

- **账号绑定**：在 Web「机器人与 AI」获取绑定码，私聊机器人发送 `绑定 绑定码`（或 `/start 绑定码`）。
- **交互卡片菜单**：私聊发送 `/start`、`菜单` 或 `主菜单` 打开卡片菜单。点击按钮优先调用 `im.v1.message.patch` 原地刷新卡片，减少群 / 私聊刷屏。
- **富文本与快捷文本命令**：支持普通文本与飞书富文本 `post` 消息。除按钮菜单和自然语言 AI 外，也支持直接发送：
  - `公账支出 35 CNY 打车`（财务管理员 / 账本所有者）
  - `成员垫付 35 CNY 打车`（旧命令 `支出 ...` 仍按成员垫付处理）
  - `收入 100 CNY 客户尾款`（财务管理员 / 账本所有者）
  - 快捷查询：`最近账目`、`余额`、`待报销`、`帮助`
  - 文本快捷记账返回待确认摘要后，发送 `确认 确认码` 入账或 `取消 确认码` 放弃。
- **媒体提示**：私聊发送图片或文件时，机器人会提示前往 Web 账目详情上传凭证（已配置 `PUBLIC_URL` 时附带入口链接）。
- **群聊使用**：在群内 `@机器人 /groupid`（不区分大小写）获取群 ID，由账本所有者在 Web「团队设置」加入飞书群允许名单。群内成员须先私聊绑定；触发命令需 `@机器人`（兼容文本与富文本 `post`），填写金额或备注时请 `@机器人` 并回复对应的机器人输入提示（兼容普通回复 `parent_id` 与话题 `root_id`）。卡片按钮仅允许发起者操作。

### 1.3 飞书工作台与内置浏览器嵌入

- Web 默认启用安全的 `X-Frame-Options: DENY` 与 `CSP frame-ancestors 'none'`（仅 `/api/entries/{id}/receipt` 在非嵌入模式下放宽为 `SAMEORIGIN` / `'self'` 以支持弹窗内 PDF 预览）。
- 如需将账本嵌入飞书工作台或文档 iframe，在 `.env` 配置：
  ```dotenv
  PUBLIC_URL=https://你的记账域名
  COOKIE_SECURE=true
  FEISHU_EMBED=true
  # 如使用私有化域名，可改用空格分隔的自定义 allowlist：
  # FEISHU_FRAME_ANCESTORS=https://your-feishu.example.com
  ```
- 同时开启 `COOKIE_SECURE=true` 与飞书嵌入且未手动指定 `COOKIE_SAMESITE` 时，服务端会自动将登录 Cookie 与 Vanora OAuth 流程绑定 Cookie（`ledger_oidc_flow`）设为 `SameSite=None`（也可显式指定 `COOKIE_SAMESITE=none`）。在 iframe 嵌入态发起 Vanora OAuth 登录时，前端会自动尝试顶层跳转或提供新窗口打开入口。
- Web 前端已内置飞书 WebView 适配：无原生 `confirm`/`prompt` 弹窗、三级降级剪贴板复制、飞书移动端 `tt.downloadFile` 下载适配与安全区留白。

### 1.4 队列与可靠性

收到的消息与待发回复先持久化到 SQLite，重复事件与重复确认不会重复入账；处理单条消息失败时有错误隔离避免阻塞队列；发送失败按上限自动重试（最多 8 次），遇到飞书永久错误码立即丢弃。处理完成后清空消息原文，仅保留去重所需的消息 ID。因平台去重有有效期，长时间断线恢复后偶发回复重复，但账目写入始终幂等防重。

参考文档：[飞书使用长连接接收事件](https://open.feishu.cn/document/ukTMukTMukTM/uYDNxYjL2QTM24iN0EjN/event-subscription-configure-)、[飞书机器人概述](https://open.feishu.cn/document/client-docs/bot-v3/bot-overview)。

## 2. 接入 Telegram

### 2.1 启动与绑定

1. 在 Telegram 找 `@BotFather` 创建机器人并获取 Token。
2. 在 `.env` 中配置 `TELEGRAM_BOT_TOKEN`（目前 Telegram Token 仅通过 `.env` 配置，不经 Web 表单存储）。若服务器需代理访问 Telegram，另配：
   ```dotenv
   TELEGRAM_PROXY_URL=http://127.0.0.1:7890
   ```
   > `TELEGRAM_PROXY_URL` 仅作用于 Telegram API，不影响 AI 或汇率请求。
3. 启动 worker：
   - 本地运行：`python -m app.bot`
   - Docker 运行：`docker compose --profile telegram up -d --no-build`（源码构建改为 `--build`）
4. 成员登录 Web「机器人与 AI」生成绑定码，私聊机器人发送 `/start 绑定码` 完成绑定。

> 若该 Token 此前配置过 Webhook，worker 会提示先在原服务停用，不会擅自删除原有 Webhook。

### 2.2 命令清单

| 命令 | 说明 | 权限要求 |
| --- | --- | --- |
| `/start` / `/menu` | 打开交互式主菜单 | 所有已绑定成员 |
| `/book` | 逐步记录一笔「成员垫付」 | 所有已绑定成员 |
| `/expense` | 逐步记录一笔「公账支出」（确认即扣余额） | 财务管理员 / 账本所有者 |
| `/income` | 逐步记录一笔「团队收入」 | 财务管理员 / 账本所有者 |
| `/ai <自然语言>` | AI 自然语言解析（多笔新增 / 修改 / 作废 / 报销 / 查询） | 随所含动作校验权限 |
| `/summary` | 查看个人待报销，按原币种列示 | 所有已绑定成员 |
| `/recent` | 分页查看最近账目（默认隐藏已作废，可切入已作废列表） | 所有已绑定成员（永久删除需财务/所有者） |
| `/team` | 分页查看团队待报销明细 | 所有已绑定成员 |
| `/funds` | 查看可用资金、结余、缺口、模拟进账与报销安排 | 所有成员查看；一键报销/入账需财务/所有者 |
| `/today` | 今日收入、公账支出与成员垫付汇总 | 所有已绑定成员 |
| `/month` | 本月收入、公账支出与成员垫付汇总 | 所有已绑定成员 |
| `/cancel` | 取消当前进行中的草稿 | 所有已绑定成员 |
| `/help` | 查看使用提示 | 所有已绑定成员 |

### 2.3 交互细节与群组规则

- **分步表单记账**：选择币种 → 输入金额 → 预览确认。预览中可选填用途与备注，并修改金额、币种、日期（财务管理员 / 账本所有者还可修改垫付人）；编辑用途或备注时发送 `-` 可清空（付款参考号与作废原因不受此规则影响）。
- **私聊自然语言**：私聊直接发送文字会自动触发 AI；若当前正在填写按钮表单，输入会用于当前步骤，发 `/cancel` 可退出或发 `/ai ...` 另起识别。
- **群组白名单**：默认仅允许已绑定成员私聊。如需群组使用，由账本所有者在 Web「团队设置」添加群组 ID（如 `-100...`）。群成员仍需先私聊绑定；群内需用命令或按钮发起，填写金额、用途、备注时**必须回复机器人发给自己的提示消息**（校验归属与步骤，避免误触发，话题群自动保留在原话题）。
- **并发与事务**：更新消费、草稿确认、账目写入与待发回复均在 SQLite 事务中执行；若账目同时被 Web 修改，机器人会提示重新核对后再保存。

参考文档：[Telegram Bot API](https://core.telegram.org/bots/api)。

## 3. 机器人资金计算与一键报销（Telegram & 飞书共用）

打开菜单「资金与付款项目」或发送 `/funds`，可查看当前可用资金、待报销、建议预留、结余、缺口与逐笔建议付款项目：

1. **模拟新进账**：点击「模拟新进账」选择币种并输入金额，仅试算不入账；财务管理员与账本所有者可点击「将这笔真实进账记入账本」经预览确认后保存为真实团队收入。
2. **自定义本次安排**：点击「设置报销预算」输入结算币种金额上限，或点击「选择报销项目」分页勾选具体项目，随时可点「恢复自动安排」。
3. **按实际余额一键报销（财务管理员 / 账本所有者）**：
   - 沿用本次预算或所选项目，**始终按已入账真实可用资金计算**（自动排除模拟进账，并已扣除已入账公账支出）。
   - 选择「按结算货币」或「按各笔记账货币」，按最早发生日期生成逐笔付款清单（余额或预算不足时仅安排可覆盖部分），列出项目、成员、实际付款、抵扣原币金额及剩余待报，支持翻页与填写批次付款备注。
   - 完成真实转账并核对无误后，点击「确认已转账，一键登记」一次性入账。
   - 若期间账本、结算设置变化或报价 / 确认超时，整批操作自动拒绝并提示重新计算；重复点击不会重复扣款，未结清余款继续留在待报销列表。
4. **单笔报销登记（财务管理员 / 账本所有者）**：在任意待报销账目详情中点「登记已付款 / 继续报销」，选择记账货币或结算货币，输入本次实付金额（发送 `全额` 结清余款）并填写付款方式 / 参考号，在确认页核对抵扣明细后保存。
